# Unmix — начало работы

Unmix записывает задачи разработки и помогает отменить выбранное решение,
сохранив нужные последующие изменения. Он создаёт отдельную рабочую копию Git,
а конфликты и смысловую адаптацию выполняет Codex или человек.

Исходники: https://github.com/light338/unmix
Релизы с исходным ZIP: https://github.com/light338/unmix/releases
Лицензия MIT. Node.js 22+, Git и начальный коммит в целевом репозитории.
Зависимостей npm, телеметрии и серверного аккаунта Unmix нет.

## Запуск

Склонируй репозиторий или распакуй ZIP релиза. В каталоге Unmix:

```sh
node bin/unmix.mjs help
node --test test/*.test.mjs
node examples/demo.mjs
```

Демонстрация магазина содержит заранее написанные исправления. Она показывает
механику пересборки, а не новый запуск модели. Описание отдельного исторического
живого прогона Codex находится в [docs/live-codex.md](docs/live-codex.md).

## Подключение

Подставь абсолютные пути к Unmix и своему небольшому тестовому проекту:

```sh
codex mcp add unmix -- node /absolute/unmix/bin/unmix.mjs mcp --repo /absolute/project
```

Проверь `/mcp` в новой сессии Codex. MCP-сервер предоставляет 14 инструментов.
Инструкции для агента и полный процесс: [docs/codex.md](docs/codex.md).
Записывать задачи нужно до редактирования; произвольную старую историю Git
Unmix не умеет надёжно делить на намерения задним числом.

## Что проверять

1. `begin` / `finish` сохраняют намерение, зависимости и снимки задачи.
2. `preview` показывает записанные зависимости и пересечения файлов до пересборки.
3. `prepare` создаёт кандидата без выбранной задачи и останавливается при блокере.
4. Агент исправляет только кандидата, затем вызывает `resume`.
5. `report` показывает исходные и получившиеся изменения по задачам.
6. `verify` выполняет заданные проверки; `inspect` показывает свежесть результатов.

Можно заранее объявить [паспорт сохранности](docs/preservation-passport.md):
обязательные сценарии с постоянными ID и автоматическими или ручными проверками.
Зелёные команды не закрывают пропущенное или устаревшее ручное требование.
Для сценария отмены нужен осмысленный провал исходной версии и успех кандидата;
автоматический критерий должен использовать описанный в руководстве маркер.

[Ручные подтверждения](docs/manual-checks.md) привязаны к снимкам файлов.
Unmix не удостоверяет личность наблюдателя и не отслеживает состояние браузера,
базы данных, внешних сервисов или окружения. Это не песочница безопасности и
не гарантия сохранения всего поведения: выводы относятся к заданным сценариям.
Команды проверок выполняют доверенный код проекта и могут иметь побочные эффекты.

Условия браузера, тестового аккаунта и данных можно объявить через
`manual-context`. Их изменение требует повторных наблюдений; автоматического
чтения браузера нет. См. [руководство](docs/manual-context.md).

С v0.2.0 можно записать готовое изменение одной командой после редактирования:
`checkpoint --title "Название изменения"`. Инициализация нужна до первого изменения.
Зависимости не угадываются; корректное применение патча не заменяет проверки поведения.
См. [checkpoint](docs/checkpoint.md).
